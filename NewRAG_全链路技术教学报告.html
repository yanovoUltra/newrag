NewRAG 全链路技术教学报告

从“上传一份财报”到“回答一个带引用的问题”，解释系统的技术栈、模块边界、每个受维护文件、每个生产类、核心数据流、评测方法、部署方式和仍然存在的工程边界。

一句话定位：NewRAG 是一个面向中英文财报的多格式文档 RAG 系统，结合结构化财务字段、稠密/稀疏向量、多路召回、RRF、可选 rerank、SSE 流式生成和证据引用。

0. 阅读口径：哪些是事实，哪些不是

本报告以当前工作树中的源码、配置、测试、评测报告和部署文件为依据。为了避免“写得很全但不真实”，先说明边界。

纳入：业务源码、配置、Docker/网关/systemd、前端页面、评测脚本、golden 数据、测试、项目设计文档。
不逐文件展开：.git、node_modules、.venv、dist、缓存、日志、临时目录、上传原文、SQLite/Qdrant/Redis 运行数据和任何密钥。它们是生成物、第三方依赖、运行数据或秘密，不是项目手写源码。

当前仓库没有根目录 README.md，因此不能把历史进展报告中“已更新 README”的陈述当作当前文件事实。生产 Compose 默认是演示后端：Mock Embedding、Mock LLM、无 rerank；真实模型适配代码存在，但需要在服务器端配置密钥并切换环境变量。

1. 项目是什么

输入
PDF、DOCX、XLSX、PNG、JPG/JPEG；可附机构、权限、财年、财季。
处理
解析版面、必要时 OCR、清洗、章节识别、Small-to-Big 切块、字段抽取、向量化、索引。
检索

SSE 流式回答、引用页码与章节、字段命中、grounding 警告、用量与状态。

2. 先懂这些 RAG 基础

术语学生版解释NewRAG 中的实现
RAG先从自己的资料中找证据，再让大模型依据证据回答。pipelines/answer.py 组织检索、生成与保存。
Chunk把长文档切成可检索的小片段。叶子块用于精确召回，章节父块用于补足上下文，形成 Small-to-Big。
Embedding把文字映射为数字向量，相似含义在向量空间距离较近。查询和文档都有 dense 向量；API 原生支持时还会获得 sparse 向量。
Dense / Sparsedense 擅长语义近义，sparse 擅长词面和稀有词。Qdrant 内分别搜索，再用 RRF 融合名次。
RRF不直接比较不同检索器的分数，而是按各自排名投票。rrf.py 用 1/(k+rank) 累加并去重。
Rerank对已召回的少量候选做更贵、更准确的相关性重排。ApiReranker 可调用 qwen3-rerank；NoneReranker 直接保留融合顺序。
HyDE先生成一段“理想答案样文”，再拿它辅助向量检索。路由判断需要时由轻量 LLM 生成，配置权重参与 dense 路。
Relay确定性证据不要完全服从概率排序，直接接力到前排。公司+指标+年份命中 financial_fields 后回填来源 chunk。
Grounding检查回答中的数字是否能在引用证据中找到。generation/grounding.py 统一数值单位后比对并发出警告。
NDCG / Recall / MRR分别看排序质量、找全程度、第一条正确结果出现得多早。eval_metrics.py、eval_ablation.py 计算。
All-Hit@k一个问题的所有相关证据是否都在前 k 内；适合多证据非指标题，但应和 NDCG/MRR/Recall 一起看。严格 All-Hit、可达子集和 Parent All-Hit 用于定位覆盖瓶颈。

3. 系统架构与运行关系

浏览器（Vue 3） ├─ /upload ───── multipart ──┐ ├─ /documents ── REST ───────┤→ Caddy:443 → Nginx:8080 → FastAPI:8000 └─ /chat ─────── POST + SSE ─┘ │ ├─ SQLite：业务元数据/字段/评测 ├─ Redis Cache：缓存/会话/nonce ├─ Redis Broker：Celery 消息 ├─ Qdrant：dense+sparse 向量与 payload └─ Celery Worker：解析/切块/嵌入/入库 外部模型（按配置启用）：Embedding API / rerank API / LLM API / PaddleOCR API

为什么分两个 Redis

缓存可淘汰，队列消息不能随便淘汰，所以职责必须分离。redis-cache 限制 384MB、策略 allkeys-lru；redis-broker 使用 noeviction。这避免缓存向量挤掉 Celery 消息。

进程边界

  • API 负责短请求和 SSE 协调，不在请求线程内硬扛生产入库。
  • worker 消费入库任务，生产并发为 2。
  • Nginx 服务静态前端并将 API 转发给 FastAPI；Caddy 负责公网 TLS 与安全响应头。
  • Qdrant、两个 Redis、API 和 worker 不直接暴露公网端口。

上传为什么不是 await file.read()

接口每次只读 1MB，在写临时文件的同时计算 SHA-256，超过 50MB 时尽早停止。成功后用 os.replace 原子移动到正式路径。同一份内容直接返回 duplicate；同机构同名不同内容先把旧记录标为 archived 并删除其检索点。

断点续跑如何工作

registry.save_stage/load_stage/stage_done 将 layout、sections、chunks、分批 vectors 和 manifest 落到 data/pipeline/{doc_id}。重试时已完成阶段直接读取。向量批次写成 vectors_00000 等文件，最终 manifest 才表示整个向量阶段完成；老的单文件格式仍可读取。

切块策略

  • 正文目标约 200 tokens，边界为 128–256；相邻正文块保留约 10% 重叠。
  • 表格保留表头、单位与分页元信息；超长表采用摘要+分页，而不是粗暴截断。
  • 章节父块默认目标 3072 tokens，为叶子命中补长上下文。
  • 语义精切只处理足够长的散文块；Mock embedding 时跳过，避免伪相似度。
  • 可选摘要块只当检索锚点；章节摘要命中后展开原文父块，降低模型编造数字的风险。

六类候选各解决什么问题

候选路擅长容易失败的地方
Dense同义表达、解释性问题、跨语言语义。对 1.20% 与 1.23% 等精确数字不敏感。
Sparse + IDF术语、专名、关键词。指标标签类题目可能被 IDF 扭曲，所以 metric 题可中和 IDF。
表格路财务表、指标行、单位。表头/跨页结构复杂时需解析和元信息辅助。
字段 relay“某公司某年某指标是多少”。依赖字段抽取正确；不确定主体时不会强行注入。
数字短语精确百分比、金额、范围。普通年份和无单位裸数字会被排除，减少污染。
章节父块趋势、多跳、综述和分散证据。父块过多会拖累前排精度与延迟。

分级降级不是“无限放宽”

当真实命中不足时，答案编排按照受控层级放宽条件，例如年份窗口、精确年份、主体过滤等；每级写入 RetrievalFallbackLog，连续没有改善可熔断。目标是“多找一点”，不是把不相关文档全部塞给模型。

6. 数据模型与存储

存储内容关键设计
SQLite / documents文件名、SHA-256、大小、状态、机构、权限、财年/财季、块数。同机构 SHA 查重；同机构文件名查替换；archived 保留版本记录。
SQLite / tasks入库任务的 stage、progress、message。前端轮询，worker/API 均可更新。
SQLite / chat_records问题、答案、引用、intent、usage。用于离线复盘和后续评测。
SQLite / eval_results评测名称、范围、metrics JSON、明细 JSON。让消融结果可追溯。
SQLite / financial_fields公司、规范指标、年份、数值、单位、来源块/页/章节。结构化精确查询与来源回填。
SQLite / number_phrase_index归一化数字+单位到 chunk/doc 的倒排。解决向量对精确数字不敏感。
SQLite / retrieval_fallback_log降级级别、触发原因、真实命中数、候选数、参数。定位召回不足和规则副作用。
Qdrantchunk dense/sparse 向量与正文、页码、章节、父子关系、权限等 payload。服务端过滤先隔离 org/visibility/year/doc，再做向量搜索。
Redis cache查询向量、语义答案、会话、nonce、命中统计。文档向量 TTL 默认为 0；缓存实例可 LRU 淘汰。
文件系统/volume上传文件和 pipeline 阶段 JSON。支持断点续跑；生产由 app_data 持久卷保存。

SQLite 初始化时启用 WAL、synchronous=NORMAL 和 5 秒 busy_timeout，并创建组合索引。这能改善单机并发，但它仍不是多 API 节点的高可用数据库。

7. API 与 SSE 协议

方法与路径用途主要返回
GET /livez只判断应用进程存活，不访问依赖。{app:"ok"}
GET /healthz并发检查 Qdrant/Redis，每项最多 1 秒，结果缓存 5 秒。app/qdrant/redis 状态，保持旧结构。
GET /api/v1/config/public前端读取上传大小、扩展名、财年下限和服务器当前年。只读公共配置。
POST /api/v1/documentsmultipart 上传并派发入库。task_id、doc_id、status；重复文件不改响应形状。
GET /api/v1/documents兼容旧列表。DocumentOut 数组。
GET /api/v1/documents/page服务端筛选和分页，limit 1–100。items/total/limit/offset。
GET/DELETE /api/v1/documents/{id}详情/彻底删除文档、向量、字段和阶段目录。文档 DTO 或删除确认。
GET /api/v1/tasks/{id}读取入库任务进度。TaskOut。
POST /api/v1/chat问题长度 1–2000；返回 text/event-stream。多种 SSE 事件。
GET /api/v1/metrics/cache只读缓存键数、内存与命中统计。缓存指标快照。

SSE 事件顺序

meta 描述 intent/检索计划；field 给出结构化指标证据；多个 token 组成答案；citation 提供引用；grounding/warning 表示证据检查；error 表示异常；done 收尾并给 usage。前端使用 fetch 读取 ReadableStream，因为原生 EventSource 不能 POST JSON。

15. 真实边界：目前还不是什么

  • 不是开箱即用的真实 AI 公网服务：生产配置当前为 mock/mock/none。它验证全栈运行、安全入口和数据流程，但真实高质量回答仍需安全配置 embedding、LLM、rerank。
  • 不是多节点高可用：SQLite 和本地/单卷 pipeline 适合单机。横向扩容需要 PostgreSQL、对象存储、共享任务状态与集群化依赖。
  • 非指标题最终排序没有 0.9：深召回已超过 0.9，但稳定 Top-8 NDCG/Recall 尚未达到。不能把 Recall@500 写成 NDCG@8。
  • 不是完整身份系统：应用内 HMAC 可选，公网入口用 Basic Auth；没有用户注册、JWT、RBAC 管理后台、密码找回或审计控制台。
  • 不是全格式无损解析：复杂合并单元格、图片表格、特殊字体和极差扫描件仍可能需要 OCR/解析器专项适配。
  • 不是完备可观测平台：已有 JSON trace 和 OTel 接口，但告警、仪表盘、SLO、在线反馈和自动回归闭环仍需部署。

17. 给学生的阅读与实践顺序

  1. 先读 frontend/src/views/UploadView.vue 和 api/v1/documents.py，跟踪一次上传。
  2. 再读 pipelines/ingest.py，每看到一个阶段就跳到 parsers/fields/splitter/store 对应文件。
